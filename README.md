# Stranger Thoughts

Talk to a stranger and get their thoughts. People will send writing. An unnamed, real person reads it and replies, often by hand, sometimes typed. This draft is a waitlist. It lists no prices and takes no payment.

The site is static HTML and CSS. GitHub Pages serves it from the repository root on `main`. There is no build step on Pages. Generated pages are committed.

The preview URL is [https://dmlehinger-web.github.io/stranger-thoughts/](https://dmlehinger-web.github.io/stranger-thoughts/). Internal links use the `/stranger-thoughts/` prefix so that preview works.

`sitemap.xml` and `robots.txt` list the public pages. `404.html` is omitted from the sitemap. There is no analytics tag and no third-party font.

## How the files fit together

- `data/site.json` — name, preview URL, waitlist address, mailing-address placeholder, and the footer.
- `data/home.json`, `data/how.json`, `data/about.json`, `data/waitlist.json`, `data/thoughts.json` — page copy.
- `data/posts/*.json` — one file per public note. Files whose names start with `_` are templates and are not published.
- `templates/page.html` — the document shell (header, footer, meta tags).
- `templates/post.html` — the individual thought page.
- `css/styles.css` — the only stylesheet. The build does not rewrite it.
- `scripts/build.py` — reads the data and writes HTML, `sitemap.xml`, and `robots.txt`.

Generated HTML starts with `Generated by scripts/build.py`. Edit the data or templates, then rebuild. The next build overwrites hand-edits to those HTML files.

## Build and preview

Python 3.9+ is enough. There are no packages to install.

```bash
python3 scripts/build.py
```

Local preview has to include the `/stranger-thoughts/` prefix, because that is how the links are written:

```bash
python3 scripts/build.py
mkdir -p /tmp/st-preview
ln -sfn "$PWD" /tmp/st-preview/stranger-thoughts
python3 -m http.server 8080 --directory /tmp/st-preview
```

Open `http://localhost:8080/stranger-thoughts/`.

## GitHub Pages

In the repository: **Settings → Pages → Build and deployment → Deploy from a branch**.

- Branch: `main`
- Folder: `/` (root)

Save. `.nojekyll` is in the root so Jekyll does not process the site. No Actions workflow is required.

On a project site, crawlers read `robots.txt` from the host root (`dmlehinger-web.github.io/robots.txt`), which this repository does not control. The copy in this repo is the one that will apply once the custom domain is serving the site from its own root.

## Custom domain, later

The planned domain is `getstrangerthoughts.com`. It is not connected. This repository omits the `CNAME` file until DNS answers. Publishing from a branch treats that file as the custom domain, and GitHub Pages then redirects the `github.io` URL to it. Adding the file early would take the preview offline.

Leave the preview on `https://dmlehinger-web.github.io/stranger-thoughts/` until the domain resolves.

When DNS is ready, do the cutover in one commit:

1. At Porkbun, point the apex at GitHub Pages. Prefer an `ALIAS` or `ANAME` record for `@` to `dmlehinger-web.github.io` if Porkbun offers it. Otherwise use four `A` records for `@`:
   - `185.199.108.153`
   - `185.199.109.153`
   - `185.199.110.153`
   - `185.199.111.153`
   - Optional `AAAA` records: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`
2. If you want `www`, add a `CNAME` for `www` to `dmlehinger-web.github.io`. The DNS `CNAME` is not the same thing as a `CNAME` file in the repo.
3. Confirm the records answer (`dig getstrangerthoughts.com`) before changing the site.
4. In `data/site.json`, set `domain_status` to `live`, `origin` to `https://getstrangerthoughts.com`, and `base_path` to `""`.
5. Add a repository file named `CNAME` whose only line is `getstrangerthoughts.com`.
6. Run `python3 scripts/build.py` and commit the JSON, the `CNAME` file, and the regenerated HTML, sitemap, and robots file together. Links drop the `/stranger-thoughts/` prefix in that build. The custom domain serves the site from `/`, so the prefix has to go at the same time as the `CNAME` file.
7. In Pages settings, confirm the custom domain. Turn on **Enforce HTTPS** after the certificate is issued. That can take a while after DNS is correct.

The build refuses a `CNAME` file while `domain_status` is `not_live`. It also refuses any mailing address other than `Mailing address coming soon`, a personal-inbox waitlist address, a social profile URL, or a street address in the copy. Change the mailing-address check in `scripts/build.py` only when a real, non-residential desk address exists.

## What this draft leaves for later

- A real waitlist mailbox. The form and the mailto link use `waitlist@strangerthoughts.example`, which does not deliver mail. The page says so. Replace it in `data/site.json` when a mailbox exists, and set `waitlist_email_is_placeholder` to `false`. The flag and the address have to agree: a placeholder ends in `.example`.
- Mail. The only address on the site is `Mailing address coming soon`.
- Payment. There is no price and no checkout.
- An X account. About and How it works say a brand account is coming. They do not invent a handle.
- Analytics, affiliate IDs, and secrets. `.gitignore` ignores `.env` and `.env.*`.
